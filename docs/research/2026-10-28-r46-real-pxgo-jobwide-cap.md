# PxGo R46 — Real 2,560 CONNECT + 600 HTTP under stricter Job Object total-commit quota, with SAME-allocation positive control

**Research/test-only; no runtime/default change or release.** Based on PR#103 R45 immutable `6c63eba9cd6a39dfcad20bf3fad3a39a73d06287`, PR#102 base `fb2aa923a753309dae515fc8be38112f45fbddc8`. Both OPEN DRAFT. The R45 Windows 10-minute soak source is unchanged by this candidate.

## Goal

R43 proved a small Windows helper's job-wide memory quota can dominate a process quota without any real proxy connection load. R45 repairs a separate 10-minute soak test-validity failure (R44 had 2,561 active immediately after short response at cycle2, original R44 run completed FAILURE). R46 integrates the **same real PxGo child** 2,560 held/authenticated CONNECT and 600 short HTTP with a child-only Job Object total-memory quota stricter than its per-process quota, and proves causality with a positive control in the SAME child after changing ONLY the job-wide cap.

## Protocol and strict acceptance

1. Opt-in only `PXGO_CAPACITY_JOB_PROXY_JOBWIDE=1` alongside existing `PXGO_CAPACITY_JOB_PROXY_2560=1`, AUTO and class ON. Existing R45/R43 Windows test behavior unchanged if env unset; no privileged runner/parent/global memory limits.
2. Parent samples child baseline native PrivateBytes. Creates one owned Job Object containing ONLY child. Sets `ProcessMemoryLimit=baseline+448MiB`, `JobMemoryLimit=baseline+384MiB` with both flags; readback exact from native handle. Child itself queries `QueryInformationJobObject(NULL,ExtendedLimitInformation)`, must see same strict job and process caps. On Windows nested jobs, this immediate query still may miss stricter ancestors; no assertion otherwise.
3. Establish **exactly 2,560 concurrently HELD real CONNECT tunnels** via 16-dial-paced ramp, payload echo proven, class governor long/physical=2560, short/provisional=0. Parent measures child PrivateBytes and derives native `probe=jobCap-private+32MiB`. Probe is 32MiB over job-wide free commit but 32MiB BELOW the unchanged per-process cap. If memory margin invalid, hard FAIL (no skip/waiver).
4. Send `JOBWIDE_PROBE\n<size>\n` to real child: one native `VirtualAlloc MEM_COMMIT|MEM_RESERVE` of calibrated bytes MUST be denied by recognizable Windows quota error, then a 4MiB native VirtualAlloc must succeed and free in SAME live PID. Marker `JOB_PROXY_JOBWIDE_PROBE denied_bytes=... recovered_bytes=4194304`.
5. **Causal positive control:** Parent temporarily raises ONLY child Job Object `JobMemoryLimit` to MATCH the unchanged higher process cap (not the process cap or host/runner). Parent sends `JOBWIDE_CONTROL\n<SAME SIZE>\n`, child re-queries both limits to prove equality, repeats EXACT allocation and now REQUIRES SUCCESS and free, marker `JOB_PROXY_JOBWIDE_CONTROL allowed_bytes=... cap_equal=true`. If same alloc does not succeed, FAIL rather than attribute original failure to job-wide cap.
6. Parent restores STRICT lower job cap (baseline+384MiB), verifies native flags and both caps exact, then same PxGo child serves **600/600 real HTTP shorts** with 2,560 long CONNECT held; after every short, payload valid, verifies original long echo integrity; eventually all 2,560 held closed and physical/class permit count zero. Emits `JOB_PROXY_JOBWIDE_RESULT ... held_connect=2560 completed_short=600 ... job_only_denied=... recovered_bytes=4194304 same_allocation_control_succeeded=true`. Old original `JOB_PROXY_2560_RESULT` and child QUIT/normal Wait remain strict.
7. Dedicated fresh pinned `windows-latest` exact-SHA workflow job, `go test` exit0 and strict FOUR positive markers (own child cap, denied/allowed same-allocation, final 2560+600); always upload raw SHA qualified logs on success/failure. Full CI uses exact immutable SHAs, all jobs paginated and terminal.
